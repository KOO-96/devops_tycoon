# 기술 필요 조건 매트릭스 (Technology Trigger Matrix)

> **하나의 문제에 하나의 정답만 연결하지 않는다**(마스터 플랜 P4). 각 대응은 비용·시간·효과·부작용이 다르다.

## 읽는 법
- "단기 대응"은 빠르지만 근본 미해결(재발 위험), "근본 대응"은 시간/개발 비용이 크지만 지속 효과.
- 도입 후 위험 열은 P6(파생 병목)을 명시한다.
- 비용/복잡도는 상대 등급(낮음/보통/높음). 절대 수치는 이벤트 카탈로그의 난이도표(Proposed) 참조.

## 복수 정답 예시 (P4 강조)

**DB 조회 부하 증가**에 대한 대안은 모두 유효하며, 선택에 따라 트레이드오프가 다르다.

| 대안 | 시간 | 비용 | 효과 지속성 | 주요 부작용 |
|------|------|------|-------------|-------------|
| 쿼리 최적화 | 보통 | 낮음 | 높음 | 개발 시간 점유 |
| 인덱스 추가 | 짧음 | 낮음 | 높음 | 쓰기·저장공간 소폭 부담 |
| Redis 캐시 | 짧음 | 보통 | 보통 | Stale/Stampede 위험 |
| Read Replica(단계 3) | 긺 | 높음 | 높음 | 복제 지연·복잡도↑ |
| 기능 제한 | 즉시 | 낮음 | 낮음 | 사용자 경험 저하 |
| 요청 Rate Limit | 즉시 | 낮음 | 낮음 | 매출 기회 손실 |

> 어떤 선택도 "무조건 정답"이 아니다. AI CTO(가디언/부스터)는 상황·성향에 따라 다른 대안을 권하되, 장점과 위험을 함께 제시한다(마스터 플랜 4.12).

## Acceptance Criteria (매트릭스 검증)

- AC: 각 문제 상황에는 서로 다른 트레이드오프의 대응이 2개 이상 존재해야 한다(P4).
- AC: 모든 근본 대응에는 비용/복잡도/도입 후 위험이 하나 이상 명시되어야 한다(P5·P6).
- AC: 매트릭스의 각 행은 이벤트 카탈로그의 이벤트 ID로 추적 가능해야 한다.
