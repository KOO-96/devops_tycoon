# Post-MVP 이벤트 백로그 (Post-MVP Event Backlog)

> MVP 최초 작업에서 **상세 설계하지 않는** 기술·이벤트를 삭제하지 않고 백로그로 보관한다(마스터 플랜 4.8 정렬).
> 여기 항목은 개략적인 필요 조건만 정리하며, 상태는 모두 **Post-MVP**다.

- 문서 버전: v0.1.0
- 작성 브랜치: `plan/event`
- 최종 수정일: 2026-07-20
- 담당 역할: Event
- 문서 상태: **Draft**
- 참고 Program 문서: `origin/plan/program:...master-plan.md` (commit `a28fd84`)

## Post-MVP 기술 백로그

| 기술 | 개략적 필요 조건(도입 트리거) | 도입 시 새 장애 후보 | 선행 MVP 기술 | 예상 단계 |
|------|-------------------------------|----------------------|----------------|-----------|
| Kafka / 메시지 큐 | 동기 처리 한계, 스파이크 버퍼링·비동기 워크로드 필요 | 소비 지연(consumer lag), 파티션 불균형, 메시지 유실/중복 | App Scaling, PostgreSQL | 3~4 |
| Kubernetes(복잡 운영) | 다수 서비스·배포 자동화·자가치유 필요 | 스케줄링 실패, 리소스 쿼터 초과, 롤아웃 교착 | 배포/CI·CD, App Scaling | 4 |
| Service Mesh | 서비스 간 트래픽 제어·mTLS·관측 필요 | 사이드카 오버헤드, 라우팅 규칙 오류 | Kubernetes | 4~5 |
| Multi Region | 지역 장애 대비·글로벌 지연 개선 필요 | 리전 간 지연, 장애 조치(failover) 실패, 데이터 정합성 | LB, PostgreSQL | 5 |
| Global Database | 글로벌 쓰기·강한 일관성 요구 | 지역 간 복제 지연, 쓰기 충돌, 일관성-지연 트레이드오프 | PostgreSQL, Read Replica | 5 |
| 복잡한 Auto Scaling | 트래픽 변동 큰 상시 운영, 수동 대응 한계 | 스케일 진동(flapping), 콜드스타트, 스케일 지연 중 장애 | App Scaling, Health Check | 3~4 |
| 대규모 마이크로서비스 | 조직·도메인 분리, 독립 배포 필요 | 서비스 간 카스케이딩, 분산 트랜잭션, 계약 불일치 | Kubernetes | 4~5 |
| 고급 분산 추적 | 다중 서비스 경로 진단 필요 | (도구) 샘플링 누락, 추적 비용 | 기본 트레이스 | 4 |

## Post-MVP 이벤트 후보(개략)

| 후보 이벤트 | 관련 기술 | 핵심 체감 | MVP 승격 조건 |
|-------------|-----------|-----------|----------------|
| Consumer Lag 폭증 | Kafka | 비동기 처리 적체 | 큐 기반 아키텍처 MVP 편입 시 |
| 리전 Failover 실패 | Multi Region | 재해 복구의 어려움 | 단계 5 콘텐츠 착수 시 |
| 오토스케일 진동 | Auto Scaling | 자동화의 역설 | 자동 스케일 MVP 편입 시 |
| 분산 트랜잭션 정합성 | 마이크로서비스 | 일관성 비용 | MSA 콘텐츠 착수 시 |
| 샤딩 핫스팟 | Global DB/샤딩 | 데이터 분포 불균형 | 단계 4~5 착수 시 |

## 규칙

- 위 항목은 **MVP 범위를 확장하지 않는다.** Program 승인 없이 MVP로 승격하지 않는다(금지사항 준수).
- 각 항목은 향후 별도 카탈로그로 상세화하며, 상세화 시 [event-design-standard.md](./event-design-standard.md) 템플릿을 따른다.
